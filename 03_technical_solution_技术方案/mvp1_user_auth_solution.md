# MVP1.1 用户注册登录技术方案

## 范围

本轮只实现个人用户注册登录和用户数据绑定，不新增组织、余额、历史文章列表等业务功能。

## 认证方式

- 注册方式：用户名 + 密码。
- 登录方式：用户名 + 密码。
- 登录态：HTTP-only Cookie，有效期 7 天。
- Cookie 只保存签名后的会话令牌，不在前端 localStorage 保存 token。
- 退出登录时清除 Cookie。

## 用户名规则

- 长度 6–32 个字符。
- 只允许英文字母、数字、下划线。
- 不区分大小写唯一。
- 显示时可保留用户输入的原始大小写。

## 密码规则

- 长度 8–64 个字符。
- 至少包含 1 个字母。
- 至少包含 1 个数字。
- 允许特殊符号，但不强制。
- 后端只保存密码哈希，不保存明文。

## 手机号绑定

- 手机号在注册后通过账号设置弹窗绑定。
- 只支持中国大陆手机号：11 位数字，第一位为 `1`，第二位为 `3-9`。
- 手机号唯一。
- 点击发送验证码后，后端生成 6 位验证码。
- 当前版本不接短信供应商，开发环境响应返回 `debug_code`。
- 验证码 10 分钟有效。
- 同一手机号 60 秒内不能重复发送。
- 绑定时提交手机号 + 验证码，验证成功后写入用户表。
- 手机号找回密码只预留入口和接口边界，不实现完整流程。

## Demo User 处理

- Demo User 继续保留为开发和测试辅助。
- 正常业务接口不再自动 fallback 到 Demo User。
- 未登录调用素材、风格、写作、段落重写等业务接口必须返回 401。
- 注册真实用户后不迁移 Demo User 的素材、风格和文章。

## 前端交互

- 未登录用户可以直接看到工作台 UI。
- 未登录用户点击会创建或访问用户资产的动作时，弹出登录/注册弹窗。
- 登录/注册成功后关闭弹窗，停留在当前工作台；不自动继续执行刚才的动作。
- 工作台右上角显示账号入口。
- 账号设置弹窗提供手机号绑定和退出登录。

## 数据隔离

所有以下数据必须绑定当前登录用户：

- `materials`
- `style_analysis_jobs`
- `style_profiles`
- `documents`
- `writing_tasks`
- `model_usage_logs`

后端必须从认证上下文获取 `current_user.id`，不能信任前端传入的 `user_id`。
