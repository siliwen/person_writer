# 2026-08-06 MVP1 工作台阶段进度记录

## 当前阶段结论

MVP1 当前已经从早期技术 Demo 调整为“个人风格写作闭环”的可运行工作台。首版仍使用固定 Demo User，不做真实注册、组织、余额和支付。当前主链路是：

上传参考作品创建新风格，或选择已有风格 → 风格确认/选择 → 输入文体、字数、主题和要求 → 调用模型生成文章 → 在正文中按自然段提出修改意见并只重写该段。

当前默认生成路径仍是 `style_prompt_only + 可编辑 Style Profile`。RAG 不作为 MVP1 默认路径，只保留为后续文章/散文实验增强方向。

## 已完成的主要能力

### 1. MVP1 主流程

- 固定 Demo User 已接入，所有素材、风格、文档都保留 `user_id` 边界。
- 支持 `.txt`、`.md`、`.docx` 批量上传。
- 上传后自动解析自然段并触发风格分析，不再要求用户先上传、再勾选素材、再点击生成草案。
- 支持多篇相似作品合并生成一个 Style Analysis Job。
- 风格分析结果需要用户确认、命名后，才保存为 active Style Profile。
- 写作时只能选择当前用户已确认的 active Style Profile。
- 生成文章按 Writing Document 和 Document Paragraph 保存。
- 支持只重写指定自然段，其他自然段不变。

### 2. 风格分析质量与展示

- 风格分析升级为 Style Profile v2：先做文本统计，再通过千问六维文风诊断 Prompt 生成结构化风格档案。
- 六维覆盖：词汇与句法、修辞与表达、叙事与结构、情感与基调、题材与素材、时代与语体。
- 前端确认区优先展示普通用户能理解的大白话诊断报告，不再直接把用户暴露在复杂 JSON 面前。
- 中文素材的分析展示强制中文化；除英文原文场景外，不向用户展示英文术语、英文括注或中英混写。
- 完整风格档案仍保留在“高级：查看和编辑完整风格档案数据”中，方便后续调试和人工校正。

### 3. 写作生成

- 写作参数已包含文体、标题/主题、写作要求、目标字数/篇幅、必须包含、必须避免。
- 新增风格贴近程度：
  - 轻度参考：只参考语气、节奏和观察方式，降低像改写稿的风险。
  - 平衡仿写：默认档位，保留可感知文风特征。
  - 高度贴近：主要用于内部测试。
- PromptComposer 已加入反照搬约束：只学习抽象风格机制，不复用原文人物、地名、事件、固定意象组合或标志性表达。
- 前端状态栏显示当前模型模式、模型名和 fallback 行为，避免用户误以为 mock 输出是千问真实调用。

### 4. 本轮交互重点调整

本轮主要解决两个产品体验问题：

第一，段落重写交互。

旧交互是在每个自然段下方常驻一个修改输入框和按钮，导致文章被切得很碎，用户难以按正常文章形态阅读全文。现在改为：

- 正文保持连续阅读形态。
- 鼠标移到自然段上时，该段背景高亮。
- 用户点击自然段或“修改这一段”后打开弹窗。
- 弹窗中展示当前段落内容，并输入修改意见。
- 提交后只重写该自然段，成功后弹窗关闭，段落在原位置更新。
- 移动端或窄屏下，“修改这一段”按钮直接显示，不依赖 hover。

第二，已有风格删除。

- 已保存风格列表增加“删除这个风格”按钮。
- 删除前有确认提示。
- 后端使用软删除，不物理删除数据库记录。
- 删除后的风格不再出现在风格库中，也不能再用于新写作。
- 历史已生成文章不受影响。
- 重复删除同一个风格保持幂等。

## 当前重要产品规则

- MVP1 不做真实个人注册登录。
- MVP1 不做组织注册、组织子账号、组织共享余额。
- MVP1 不做余额、充值、扣费；只记录 token 和估算成本。
- 用户素材默认私有，不参与训练。
- 当前内部评测材料按用户要求跳过授权审查，但该例外不自动扩展到训练、微调、公网演示或商业宣传。
- 后续每次产品或交互修改，应先给出方案，等用户确认后再改代码。
