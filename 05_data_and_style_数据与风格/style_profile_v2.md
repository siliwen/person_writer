# Style Profile v2

## 目的

Style Profile v2 用于把用户上传的多篇作品转成可编辑、可执行、可验证的个人文风档案。它不是普通文学评论，而是后续 `PromptComposer` 生成文章时的核心风格约束。

## 生成策略

1. 系统先做客观统计：作品数、字数、自然段数、平均段落长度、句长分布、标点分布、高频词。
2. 系统把统计结果和代表段落提交给模型做六维分析。
3. 模型必须输出结构化 JSON。
4. 如果模型异常或输出不是合法 JSON，系统回退到本地生成的 Style Profile v2 草案。

## 六维分析

- 词汇与句法层：词性偏好、具象/抽象比例、句长分布、标点习惯。
- 修辞与表达层：意象来源、比喻机制、感官侧重、幽默或讽刺机制。
- 叙事与结构层：叙事视角、开篇方式、发展方式、对话风格、结尾方式。
- 情感与基调层：情绪浓度、克制程度、核心母题、思想底色。
- 题材与素材层：核心场景、人物原型、适合和不适合的题材。
- 时代与语体层：语言时代感、书面/口语比例、方言或地域语法。

## 核心字段

- `style_summary`：给用户看的风格摘要、稳定特征、不稳定特征和置信度。
- `source_stats`：客观文本统计。
- `lexical_style`：名词、动词、形容词、语体和禁用词偏好。
- `syntax_style`：句长、段落长度、标点和句式规则。
- `rhetoric_style`：意象、比喻、感官和幽默/讽刺机制。
- `narrative_style`：视角、开篇、发展、对话、结尾。
- `emotional_tone`：情绪浓度、克制程度、母题和思想底色。
- `topic_boundary`：适合/不适合的题材边界。
- `language_period_style`：时代语感、书面/口语、方言或地域特征。
- `generation_rules`：真正喂给写作链路使用的可执行规则。
- `display_report`：给普通用户确认风格用的大白话报告。
- `evidence_map`：风格判断对应的材料和段落位置，不保存大段原文。
- `split_recommendation`：当多篇作品风格差异大时，建议拆分风格档案。

## display_report

`display_report` 和 `generation_rules` 分工不同：

- `display_report` 给人看，目标是让用户判断“系统是否真正读懂了原作者风格”。
- `generation_rules` 给模型用，目标是让后续写作任务能稳定执行这些风格约束。

`display_report` 包含：

- `plain_summary`：一句大白话总判断，例如“我们理解到：这位作者常从具体画面进入，情绪藏在场景里，不急着讲道理。”
- `dimensions`：六个维度的人话诊断：
  - 词汇和句子
  - 修辞和表达
  - 叙事和结构
  - 情绪和基调
  - 题材和人物
  - 时代和语体
- `writing_rules_plain`：面向用户解释的“以后仿写时必须做到/必须避免”。
- `evidence_plain`：判断依据，只显示作品和段落位置，不展示大段原文。

## 约束

- 不把用户原文长句写进风格档案。
- 不把 Style Profile 当作内容素材库。
- 生成时 `generation_rules` 优先于泛泛的文学评价。
- 界面默认展示 `display_report`，完整 JSON 只作为高级编辑入口。
- 用户确认前可以编辑 JSON；确认后进入个人风格库。
