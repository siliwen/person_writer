# 个人风格学习方案

## 第一阶段：RAG + 结构化风格档案

首版采用“结构化风格档案 + 多租户 RAG + 用户反馈”，不做微调。

原因：

- 用户早期素材量通常不足。
- 每个用户单独训练成本高。
- 训练数据授权和删除权处理复杂。
- RAG 方案可解释、可回滚、可版本化。

用户数据默认私有，不参与训练。未来如果推出个人 LoRA 或专属模型训练，应作为单独收费能力，并要求用户对训练素材和修改反馈进行单独、明确授权。

## 素材要求

建议引导用户上传：

- 至少 5 篇以上个人文章，或 8000 字以上文本。
- 每种文体单独建档，不把诗歌和公众号文章混在一个风格档案里。
- 用户可标记代表作、普通作品和不希望模仿的旧作品。
- 素材必须由用户拥有权利或取得授权。

## 风格提取

系统应从素材中提取：

- 主题偏好。
- 开头方式。
- 结尾方式。
- 句长分布。
- 标点使用习惯。
- 修辞类型。
- 常见意象。
- 叙述距离。
- 情绪强度。
- 结构模式。
- 禁用表达。

## 反馈闭环

每次生成后保存：

- 生成稿。
- 用户最终修改稿。
- 用户评分。
- 用户选择的重写理由。
- 使用的风格档案版本。
- 召回的素材片段。
- 模型和 Prompt 版本。

这批数据用于改进检索、Prompt 和风格档案。只有用户明确授权后，才进入后续训练集。

## 何时考虑微调

满足以下条件后再评估：

- 至少有一批高质量、授权清晰的“生成稿到用户修改稿”数据。
- RAG 和 Prompt 已经做过多轮评测，仍无法满足风格一致性。
- 单用户或用户群体有足够付费价值覆盖训练成本。
- 删除权、授权撤回和训练数据血缘已经设计清楚。
