# 首页自由写作与优化提示词 - 产品设计

> 状态：方案锁定，待开发（2026-08-12）
> 关联技术方案：`03_technical_solution_技术方案/free_write_technical_design.md`

## 一、背景与目标

当前首页（默认视图 `styles`）以「风格库」为核心入口，新用户必须先上传作品、创建风格才能生成文章，首屏门槛高。本设计在首页新增「自由写作」大输入框：用户直接写一句话提示词即可生成文章，不依赖风格库；并提供「优化提示词」按钮，用大模型把简短需求扩展成完整写作要求。

目标：

- 降低新用户首次使用门槛，10 秒内看到生成结果。
- 让老用户临时写「不关心个人风格」的内容。
- 给首页一个明确的行动召唤（CTA）。

## 二、已锁定决策

| 项 | 决策 |
|---|---|
| 首页默认视图 | 改为 `dashboard` |
| 无风格入口名称 | 「自由写作」 |
| 生成后着陆页 | 跳转现有 `writing` 视图 |
| 后端默认风格 | 不需要，直接按用户提示词 + 系统优化提示词提交 |
| 无风格文章鉴评 | 暂不做 |
| 优化按钮位置 | textarea 右下角 |
| 优化功能费用 | 固定扣 1 积分 |
| 优化提示词管理 | 超管后台可配置；后台仅管理 `optimize_prompt` 这一个用途 |
| 配置存储 | `prompt_templates` 表（SQLAlchemy 声明，跨 SQLite/PostgreSQL 兼容） |

## 三、首页结构变化

默认视图改为 `dashboard`。`DashboardView` 顶部新增「自由写作」区域（`FreeWriteBox`），原有统计卡片、快捷入口、我的风格、最近文章全部保留并下移。

```
┌─────────────────────────────────────────────────────┐
│  工作台                                              │
├─────────────────────────────────────────────────────┤
│     今天想写什么？                                    │
│   ┌─────────────────────────────────────────┐       │
│   │  textarea（多行，占位符轮播）              │       │
│   │                        [优化提示词]        │  ← 右下角
│   │  文体 ▼  字数 ▼  风格 ▼      [生成·X积分] │       │
│   └─────────────────────────────────────────┘       │
│  [散文] [诗歌] [杂文] [故事]   ← 文体快捷 chip        │
├─────────────────────────────────────────────────────┤
│  统计卡片 / 快捷入口 / 我的风格 / 最近文章（保留）    │
└─────────────────────────────────────────────────────┘
```

## 四、交互流程

```
DashboardView 自由写作输入
        │
        ▼
用户输入一句话需求 → （可选）点击「优化提示词」扩写并回填
        │
        ▼
点击「生成文章」→ 前端解析文体/字数/主题
        │
        ▼
POST /v1/writing-tasks（style_profile_id 为空 = 自由写作）
        │
        ▼
后端 compose_free_prompt → 调用模型
        │
        ▼
返回 document → 跳转 writing 视图展示结果
        │
        ▼
用户可保存 / 下载 / 或「按我的风格重写」
```

## 五、优化提示词交互

### 5.1 位置

在 `FreeWriteBox` 的 textarea 右下角，紧贴输入框下方右侧，文案「优化提示词」。

### 5.2 状态机

| 状态 | 按钮文案 | textarea |
|---|---|---|
| 初始 | 优化提示词 | 正常 |
| 优化中 | 优化中…（disabled + 转圈） | disabled |
| 优化成功 | 重新优化 | 内容替换为优化结果，边框短暂高亮（info 色） |
| 优化失败 | 优化提示词 | 正常，下方显示错误提示 |

### 5.3 回填行为

- 优化结果**替换**输入框内容（不是追加）。
- 回填后不自动解析文体/字数选择器，用户下一步点生成时再解析。
- 用户可继续手动编辑优化后的文本。
- 优化只是可选的「前置润色」，不强制；用户也可直接生成（系统仍会在后端做通用包装）。

### 5.4 积分

优化按钮显示「优化提示词 · 1 积分」，与生成按钮的 `btn-cost` 规范一致。生成前的积分预校验需把优化纳入：积分不足时按钮 disabled 并提示。

## 六、文体 / 字数 / 风格选择器

- 文体下拉：散文 / 诗歌 / 杂文 / 故事。
- 字数下拉：800字 / 1200字 / 2000字（诗歌默认 12 行）。
- 风格下拉：默认「自由写作」；其余为用户的个人风格（如「我的散文风格」）与推荐风格。
- 文体快捷 chip：散文 / 诗歌 / 杂文 / 故事，点击即设文体。

## 七、生成后着陆页

跳转现有 `writing` 视图，需支持无风格状态：

- `WritingView` 默认选中第一个风格；自由写作进入时不强制 `selectedStyleId`，风格选择器显示「自由写作」。
- 结果展示、保存、下载、段落重写全部复用现有逻辑。
- 段落重写时因无风格档案，prompt 不带 Style Profile，按通用要求重写。

## 八、鉴评与积分

- 优化功能：固定扣 1 积分（首版不免费，避免滥用）。
- 生成功能：积分计算与现有文章生成一致，按字数档位预估并扣减；生成按钮显示「生成文章 · 预计 X 积分」。
- 无风格文章：暂不鉴评。自动鉴评逻辑跳过 `style_profile_id` 为空的文档；手动鉴评接口对无风格文档返回 422，提示「自由写作文章暂不支持鉴评」。

## 九、占位符轮播

输入框 placeholder 循环展示：

- 例如：写一篇关于街角旧书店的散文，1200字，温暖克制
- 例如：以「迟到」为题写一篇叙事散文
- 例如：写一首关于夏末傍晚的短诗
